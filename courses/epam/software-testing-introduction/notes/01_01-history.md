# 01_01 — The History of Software Testing

## Key ideas

- **1950s–60s:** no testing profession yet. Programmers debugged their own code. "This is not 'Testing' yet — it is just some activity during development."
- **1970s:** the first real attempts — **positive testing** ("prove it works") and **negative testing** ("prove it fails"). Both failed alone, but they built the base: the two directions.
- **1980s:** testing becomes a recognized profession: its own phase in the lifecycle, **error prevention** (reviews, standards — the seed of QA), first automation attempts.
- **1990s:** **Quality Assurance** appears; testing gets closer to development; tools and systems. "Testing looks a lot like today."
- **2000s:** **Agile + TDD**: testing becomes an **inseparable part** of development — not a phase, a constant.
- **Now:** testing is part of Development/DevOps, and the base for CI/CD.

## The tricky part (the thread of the story)

Testing started **inside** development (without being "testing") → moved **out** as a separate phase → came back **in** with Agile, now as a professional, continuous part.

That is why the lesson's answer is: **closely integrated from the very beginning? No — the close integration is modern (Agile).**

## Example

1970s, a login screen: "Does it work with a correct password?" (positive) and "What happens with an empty password?" (negative). Two directions — still the core of testing today.
