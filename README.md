## Reglas del sprint

1. **Un entregable por curso.** Un curso está terminado solo cuando tiene notas, al menos un ejercicio aplicado y evidencia de finalización.
2. **Cada ejercicio va a un proyecto personal.** El curso es la excusa; el proyecto es el entregable.
3. **El roadmap está en pausa, no abandonado.** Las unidades nuevas del roadmap se retoman el 2026-11-28. Durante el sprint continúan los repasos espaciados de la Unidad 1.
4. **Sin certificado sin práctica.** Aprobar un curso no es dominarlo. Las notas y los artefactos aplicados son la evidencia real.
5. **Solo se marca el progreso verificado.** Una casilla se marca cuando existe la evidencia, no cuando se vio la clase.

## Mapa del repositorio

| Ruta | Qué contiene |
|---|---|
| `units/` | Notas de conceptos por unidad. La Unidad 1 (fundamentos) es la base actual. |
| `courses/` | Notas de cursos externos. El material original (PDFs, videos) es privado y no se publica. |
| `projects/` | Proyectos personales de QA usados como campo de práctica y piezas de portafolio. |
| `evidence/` | Artefactos sueltos: reportes de bugs, casos de prueba, charters, informes. |
| `log/` | Registro diario de estudio, se mantiene local. |
| `docs/` | Roadmap y trackers, se mantienen locales. |

## Por qué existe este repositorio

- Para hacer el progreso visible y honesto, incluidos los huecos.
- Para convertir la teoría de los cursos en artefactos que pueda mostrar.
- Para dejar un registro de lo que realmente hice, no de lo que planeé hacer.
